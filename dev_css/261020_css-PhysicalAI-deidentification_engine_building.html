보안 기반 비식별화 엔진 구축 제안

2026-10-20 · DataForge팀

개요 및 설계 원칙

원본 데이터, 암호키, 가명 매핑 테이블은 사내 보안 영역 밖으로 나가지 않게 하는 구조를 제안합니다. 사내 영역 안에서 등급 분류, 비식별 변환, 검증, 승인을 모두 끝낸 데이터만 하드웨어 일방향 망연계(데이터 다이오드)를 거쳐 외부 AI 협업 영역으로 전달합니다.

범위는 용역 ② 보안 기반 비식별화 엔진입니다. 수집 인프라(①)가 넘겨준 원본을 받는 지점부터 외부 AI 분석망(총괄 2·4세부, 인지)에 데이터를 전달하는 지점까지 다룹니다. AI 가이던스 역방향 경로(④)는 역정규화 접점만 포함합니다.

설계 원칙

  1. 원본 비반출: 원본, 키, 매핑 테이블은 사내 보안 영역에만 둡니다.
  2. 기본 차단(Default Deny): 정책에 등록되고 승인된 항목만 반출합니다. 미등록 태그는 자동으로 차단합니다.
  3. 단일 변환 라이브러리: 실시간 처리와 배치 처리가 같은 Python 패키지(deid-core)를 써서 결과가 항상 일치하게 합니다.
  4. 학습 가능성 보존: 가명 토큰을 일관되게 부여해 Heat-Billet-Coil 계보를 유지합니다. 물리량은 단위 그룹별로 동일한 변환을 적용해 물리 관계를 보존합니다.
  5. 물리적 일방향: 반출은 하드웨어 데이터 다이오드로만 합니다. 역방향(가이던스 수신)은 별도 채널로 분리합니다.
  6. 전 과정 감사: 반출 건마다 정책 버전, 키 버전, 해시, 승인자를 기록합니다.
  7. 팀 표준 스택 재사용: 폐쇄망 Kubernetes(Harbor, Gitea, ArgoCD), Python, PostgreSQL(CloudNativePG)을 그대로 활용합니다.

데이터 보안 등급 및 비식별 기법

모든 태그와 품질 항목에 4단계 보안 등급을 부여하고, 등급과 데이터 유형에 따라 변환 기법을 정합니다. 등급은 1단계 태그리스트 작성 때 함께 부여하고, 세아창원특수강 보안팀이 최종 승인합니다.

물리 일관성과 보안 수준의 한계

  • 비선형 물리식 문제: 아핀 변환은 선형식을 보존하지만, 복사열(T⁴)이나 아레니우스 식 같은 비선형 항은 깨집니다. 해결 방법은 세 가지입니다. AI 개발사가 물리식을 정규화 좌표로 다시 쓰거나, 사내에서 무차원 수 같은 물리 파생 피처를 계산해 반출하거나, 해당 변수 학습을 사내 환경에서 수행하는 것입니다. 어느 방법을 쓸지 1단계에서 인지·총괄 4세부와 합의해야 합니다.
  • 정규화는 암호화가 아닙니다: 녹는점이나 상변태 온도 같은 알려진 기준점을 이용하면 a, b를 역추정할 수 있습니다. 따라서 정규화 단독으로는 부족하고, 외부 협업 영역의 접근통제, 다운로드 차단, 수신 기관별 반출 이력 추적, 보안 서약을 함께 적용해야 합니다. 이 잔여 위험의 수용 여부는 세아 보안팀의 판단을 받아야 합니다.
  • 역정규화 접점: 외부 AI는 정규화된 값으로 학습하므로 추천 Set-point도 정규화 값으로 나옵니다. 이 값을 실제 단위로 되돌리는 역정규화는 파라미터가 있는 사내 영역에서만 수행하고, 그 결과를 인터락(④)으로 넘깁니다.

물리 서버 구성도 및 서버 스펙

서버 16대와 데이터 다이오드 1조를 4개 보안 영역에 나눠 배치합니다. 비식별 처리는 사내 보안 데이터 영역에서 끝나고, 반출 DMZ와 외부 AI 협업 영역에는 승인된 비식별 데이터만 존재합니다.

강조 표시된 비식별 워커와 다이오드 송수신부가 이 용역의 핵심 장비입니다. 외부 기관은 외부 AI 협업 영역에만 접속하며, 사내 영역에는 도달할 수 없습니다.

네트워크 구성도

네트워크는 VLAN 6개로 분리하고, 모든 영역 경계에 방화벽을 둡니다. 반출 DMZ와 외부 AI 협업 영역 사이는 방화벽이 아닌 하드웨어 다이오드로 끊어, 외부에서 사내로 들어오는 패킷 자체를 불가능하게 합니다.

화살표는 연결을 여는 방향입니다. 외부 기관은 FW-5를 통해 제공 API에만 접근합니다. 점선의 역방향 채널은 AI 가이던스 수신용(④ 범위)으로, 별도의 역방향 다이오드와 고정 스키마 메시지만 허용하는 방식을 권장합니다.

서비스 구성도 및 서비스 스펙

실시간 비식별과 배치 비식별은 같은 변환 라이브러리(deid-core)를 쓰고, 두 경로 모두 검증 서비스와 반출 승인을 통과해야 스테이징으로 나갑니다. 사내 서비스는 팀의 폐쇄망 Kubernetes(Harbor, Gitea, ArgoCD)에 배포합니다.

점선은 제어 흐름입니다. 정책 서비스가 변환 규칙을, Vault가 키와 파라미터를 두 비식별 경로 모두에 공급합니다. 가명 매핑 저장소와 감사 로그는 모든 서비스가 기록하는 공용 저장소입니다.

다이오드는 TCP 응답이 없어서 Kafka를 그대로 통과시킬 수 없습니다. 장비가 제공하는 일방향 Kafka 복제 기능을 쓰거나, 파일 전송 후 수신 측에서 Kafka로 재발행하는 방식을 장비 선정 때 확인해야 합니다.

데이터 처리 순서도

데이터 한 건이 외부로 나가려면 등록 여부, 등급, 검증, 승인 네 관문을 모두 통과해야 합니다. 하나라도 걸리면 반출되지 않고 격리되거나 반려됩니다.

실시간 경로는 사전에 승인된 정책 버전에 해당하면 ‘반출 승인됨’을 자동으로 통과하고, 배치 데이터셋은 건별로 승인자가 확인합니다. 다이오드는 수신 측 오류를 송신 측에 알릴 수 없으므로, 무결성 오류는 수신 측 경보를 보고 운영자가 재전송을 요청하는 방식입니다.

데이터 처리 흐름도

데이터는 원본 → 비식별 → 반출 패키지 → 제공 데이터셋 순서로 형태가 바뀝니다. 정책, 키, 가명 매핑 같은 통제 데이터는 한 번도 사내 영역을 벗어나지 않습니다.

아래쪽 역방향 흐름은 ④ 범위와의 접점입니다. AI가 정규화 좌표로 낸 추천값은 사내에서만 실제 단위와 원본 소재 ID로 복원되고, 인터락 검사를 거쳐 PLC에 반영됩니다.

단계 데이터 형태 위치 보관 (제안)
원본 raw.* 토픽, 원본 Parquet 사내 Kafka, MinIO 토픽 7일, Parquet은 세아 보존 정책에 따름
비식별 deid.* 토픽, 결과 Parquet 사내 Kafka, MinIO 재반출에 대비해 과제 기간
반출 패키지 Parquet + manifest + SHA-256 서명 반출 DMZ 스테이징 수신 확인 후 30일
제공 데이터셋 Parquet, Kafka 스트림 AI 협업 영역 과제 기간, 종료 시 파기 확인서
통제 데이터 정책, 키, 매핑, 감사 로그 사내 전용 감사 로그는 사내 규정 기간

기능별 시퀀스 다이어그램

핵심 기능 네 가지의 서버·서비스 간 호출 순서입니다. 실선은 요청, 점선은 응답, 굵은 파란 선은 다이오드 전송입니다.

① 정책 등록·승인·배포

보안팀이 반려하면 1단계로 돌아갑니다. 워커는 Git에 태그된 승인 버전만 읽으므로, 승인되지 않은 규칙이 운영에 들어갈 경로가 없습니다.

② 실시간 비식별·반출

워커는 키와 파라미터를 짧은 TTL로 캐시해 Vault 호출을 줄입니다. 반출은 검증 서비스가 통과시킨 시간 구간(예: 1분 단위)만 묶어서 보내므로, 실시간 지연은 수 초에서 1분 내외가 됩니다.

③ 배치 데이터셋 비식별·승인·반출

배치는 학습용 데이터셋이나 MES·LIMS 이력처럼 규모가 큰 반출에 씁니다. 승인자는 검증 보고서(위험 점수, 누출 스캔 결과, 행·컬럼 수)를 보고 건별로 판단합니다.

④ AI 가이던스 역정규화

역방향 채널과 인터락은 ④ 범위이지만, 역정규화에 필요한 파라미터와 매핑이 비식별 엔진에 있으므로 접점을 여기서 정의합니다. 역방향 메시지는 미리 정한 태그와 값 범위만 담을 수 있는 고정 스키마로 제한합니다.

키 교체 (참고)

HMAC 키를 교체하면 같은 소재의 토큰이 바뀌어 과거 데이터와 조인이 끊깁니다. 그래서 키는 데이터셋(학습 버전) 단위로 발급하고, 교체는 새 학습 버전을 만들 때 전체 재처리와 함께 수행합니다. 키 유출이 의심될 때는 즉시 폐기하고 외부 데이터셋 파기를 요청합니다.

단계별 구축 계획

계약서의 4단계에 맞춰 비식별 엔진을 단계적으로 구축합니다. 가장 중요한 선행 조건은 1단계의 등급 정책 승인(G1)으로, 이것 없이는 엔진이 무엇을 어떻게 변환할지 정할 수 없습니다.

기간은 계약 기간(2026.08~2030.12)을 네 단계로 나눈 제안이며, 총괄 과제 일정에 맞춰 조정해야 합니다. 배치 반출을 먼저 열면 AI 개발사가 실시간 연계를 기다리지 않고 학습을 시작할 수 있습니다.

리스크 및 확인 필요 사항

가장 큰 리스크는 기술보다 합의입니다. 비식별 강도와 AI 학습 품질 사이의 균형, 그리고 잔여 위험의 수용 주체를 1단계에서 문서로 확정해야 이후 단계가 흔들리지 않습니다.

리스크 영향 대응
비식별이 강해 PINN 학습 품질 저하 AI 성과 미달 책임이 데이터 쪽으로 전가 1단계 PoC에서 변환 전후 학습 성능 비교, 기법 선택을 4세부·인지와 공동 서명
정규화 값의 역추정 (알려진 물리 기준점 이용) 국가핵심기술 노출 접근통제·다운로드 제한·반출 이력 추적 병행, 잔여 위험은 보안팀 수용 결정으로 문서화
다이오드가 Kafka·실시간 전송을 지원하지 않음 실시간 반출 지연 또는 불가 장비 선정 시 일방향 Kafka 복제 또는 고빈도 파일 전송 성능 시험(BMT) 필수
미등록 태그 증가 (현장 태그 추가) 데이터 누락, 차단 경보 폭증 태그 변경 시 정책 등록을 의무화하는 변경관리 절차
역방향 채널 요구로 일방향 원칙 훼손 보안 인증·승인 지연 역방향은 별도 다이오드 + 고정 스키마로 분리 설계 (④와 공동)
키·매핑 유실 역추적과 가이던스 복원 불가 Vault 스냅샷·매핑 DB 백업을 오프라인 매체에 이중 보관

  • 외부 AI 협업 영역의 위치: 세아 IDC 내 분리망인지, 외부 기관 시설인지
