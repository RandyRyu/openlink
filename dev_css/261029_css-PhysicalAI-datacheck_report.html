요청 사항 정리

01_요청사항_정리.md
  • 작성일: 2026-10-29
  • 대상 스프레드시트: 261029_경남피지컬AI_예상 세부모델 및 태그 리스트(인이지)
  • 관련 Confluence: DataForge팀(DPE) 스페이스 > 경남 피지컬AI 폴더 (folder id 2874769409)

1. 배경

  • 과제: 세아창원특수강(고객) · 인이지(AI 개발사) · VNTG DataForge팀(OT/IT 데이터 연계·보안 게이트웨이)의 "경남 피지컬AI" 과제
  • 2026-10-21 현업 미팅(창원) 이후, 인이지가 2026-10-29 메일로 "예상 세부모델 및 태그 리스트" 를 보냄
  • 이 시트는 인이지가 5개 개발 목표 모델에 필요할 것으로 예상하는 데이터 항목(158개)을 정리한 것. 세아창원특수강이 그 데이터를 보유하고 있는지 표시하는 용도
  • 시트 '개요' 안내: 보유 여부는 표시만 하면 됨. 정확한 태그 확인은 NDA 이후 인이지가 직접 함(회신 필수 아님). 신규 센서 설치는 전제하지 않음

2. 요청 작업

  1. MES Oracle DB(cssmes, 계정 sdp_data)에서 접근 가능한 스키마·테이블 확인
  2. DataForge PostgreSQL DB(stats_db)에서 수집 테이블·수집 태그 정보 확인
  3. 시트 158개 항목별로 두 DB의 근거를 매칭해 "보유 여부"(I열) 값 결정
  4. 단계별 결과를 md 파일로 정리 (토큰 부족 시 중간 저장 후 재개 가능하게)

4. 입력 규칙 (시트 '개요' 기준)

I열은 드롭다운(데이터 유효성)으로 아래 4개 값만 허용됨.

코드 정의
보유 데이터가 저장되어 있고 제공 가능
일부 보유 일부 기간·설비·위치만 있거나 수기 기록
미보유 측정·기록하지 않음 또는 해당 공정 없음
확인 필요 담당 부서 확인이 필요함

5. 판정 원칙 (이번 작업에서 적용)

  • DB에서 테이블·컬럼·태그와 실제 데이터(행 수, 기간)까지 확인되면 → 보유
  • 일부 설비·공정·기간만 확인되거나, 해당 공정 일부만 확인되면 → 일부 보유
  • 기준·설계 자료(도면, 물성, 단가 등)처럼 DB 밖 문서일 가능성이 크고 DB에서 근거가 없으면 → 확인 필요
  • DB 권한이 없어 확인할 수 없는 경우도 → 확인 필요 (근거 칸에 "권한 없음" 명시)
  • 미보유는 공정이 없다는 사실이 DB로 명확할 때만 사용 (DB에서 못 찾았다는 것만으로는 미보유로 판정하지 않음)
  • 시트에 값을 넣기 전에 판정 결과 md(04)를 먼저 검토받는 것을 전제로 함

02_MES_Oracle_조사결과.md
  • 조사일: 2026-10-29

1. 권한 현황

→ "권한이 없을 수 있다"는 우려와 달리 이번 판정에 필요한 테이블은 모두 조회 가능했음.

주의: 테이블 통계(NUM_ROWS, LAST_ANALYZED)는 대부분 2024-07 기준으로 오래됨. 그래서 실제 데이터 기간은 날짜 컬럼으로 따로 확인함. 일부 날짜 컬럼에 9999-12-31, 1111-11-11 같은 더미 값이 섞여 있음.

4. 시사점

  • 소재 ID 추적(Genealogy)이 이미 구현돼 있음: 공정별 *_id_matching, *_idtracking, zone_tracking 이 태그 시계열을 Heat·LOT에 연결. 킥오프 회의의 "소재 ID 트래킹 구조 구축" 발언과 일치

  • 회의 메모: 2020년부터 데이터가 있으나 온전한 기간은 2023년 이후, NTP 미동기로 시간 보정 필요 (킥오프 회의 3)
