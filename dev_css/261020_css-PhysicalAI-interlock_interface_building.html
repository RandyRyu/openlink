양방향 안전 인터락 인터페이스 구축 제안

2026-10-20 · DataForge팀

개요 및 설계 원칙

AI는 추천만 하고, 운전값을 바꾸는 최종 권한은 현장 PLC와 작업자에게 둡니다. 추천값은 L1 소프트웨어 가드, L2 PLC 하드코딩 인터락, 작업자 승인 세 겹을 지나야 운전 Set-point가 됩니다. 작업자는 언제든 하드와이어 버튼으로 즉시 이전값으로 되돌릴 수 있습니다.

범위는 용역 ④ 양방향 안전 인터락 인터페이스입니다. ② 비식별 엔진에서 역정규화된 가이던스를 받는 지점부터 HMI·PLC 반영, 차단·롤백, 결과 피드백까지 다룹니다. 기존 설비 보호 계통(SIS, 하드와이어 트립)은 변경하지 않습니다.

설계 원칙

  1. AI 경로는 안전 기능이 아닙니다: AI 가이던스 경로는 비안전(non-safety) 기능으로 분류합니다. 기존 설비 보호 계통은 그대로 두고, AI 경로가 이를 우회할 수 없게 합니다.
  2. PLC가 최종 권한: 상·하한과 변화율 한계는 PLC 프로그램에 상수로 하드코딩합니다. 네트워크로 바꿀 수 없고, 변경은 변경관리(MOC) 절차로만 합니다.
  3. 외부는 대기 레지스터까지만: Writer는 PLC의 ‘AI 추천 대기 레지스터’에만 씁니다. 운전 Set-point 반영은 PLC 내부 로직이 검사와 승인을 확인한 뒤 수행합니다.
  4. OT는 끌어온다: OT로 들어오는 신규 세션은 없습니다. OT 쪽 Writer가 OT DMZ 브로커에 접속해 가이던스를 구독합니다.
  5. 고장 시 안전 측(Fail-safe): 통신 단절, 유효시간 만료, 검사 실패는 모두 ‘현재값 유지 + AI 모드 해제’로 끝납니다.
  6. 언제든 되돌림: 적용 직전 값(LKG, Last Known Good)을 PLC에 보관하고, 하드와이어 롤백 버튼으로 즉시 복귀합니다. 적용과 복귀 모두 램프(bumpless)로 처리합니다.
  7. 권한은 단계적으로 확대: 자문(표시만) → 승인형 → 제한 자동 순으로, 시험과 실증을 통과할 때마다 한 단계씩 엽니다.
  8. 표준 준수: IEC 62443 존·콘딧 모델(목표 보안 수준 SL2), ISA-101 HMI 설계 원칙을 따릅니다.

운전 모드는 네 단계로 나누고, 상위 모드는 물리 키스위치와 HMI 선택이 모두 일치해야만 켜집니다. 하위 모드로는 언제든 즉시 내려갈 수 있습니다.

물리 서버 구성도 및 서버 스펙

신규 서버는 OT DMZ 게이트웨이 2대와 OT 제어망 Writer 4대, 시험용 벤치 1대이며, 역방향 다이오드 1조를 추가합니다. 사내 영역 서비스는 ② 비식별 엔진의 Kubernetes 클러스터에 함께 올리고, PLC와 HMI는 기존 장비에 로직과 화면만 추가합니다.

강조된 장비가 핵심입니다. 게이트웨이는 사내와 OT 사이의 유일한 중계 지점이고, PLC는 하드코딩 인터락으로 최종 판단을 내립니다. 키스위치와 롤백 버튼은 네트워크를 거치지 않고 PLC 입력에 직접 배선합니다.

네트워크 구성도

사내에서는 OT DMZ 브로커로 밀어 넣고, OT에서는 같은 브로커에서 끌어옵니다. 따라서 DMZ에서 OT로 들어가는 신규 세션은 하나도 없고, 외부 AI 영역에서 사내로는 물리 일방향 다이오드로만 들어옵니다.

서비스 구성도 및 서비스 스펙

추천값은 사내에서 실제 단위로 복원된 뒤 OT DMZ 브로커에 올라가고, L1 가드의 판정을 받은 것만 Writer가 가져가 PLC 대기 레지스터에 씁니다. PLC 인터락 FB가 마지막으로 검사해 운전값에 반영하거나 거부합니다.

점선은 결과와 기준값의 흐름입니다. L1 가드의 판정과 Writer가 읽은 PLC 상태는 결과 토픽으로 돌아와 이력 DB에 쌓이고, 피드백 수집기가 이를 ② 경로로 AI 측에 돌려보냅니다.

데이터 처리 순서도

추천값은 서명, 신선도, L1 범위, 작업자 승인, PLC 인터락의 다섯 관문을 모두 지나야 적용됩니다. 적용 뒤에도 PLC가 공정값을 감시해 이상이 보이면 스스로 이전값으로 되돌립니다.

어느 관문에서 걸리든 운전값은 바뀌지 않습니다. 차단·만료·거부 사유는 모두 이력 DB에 남고, 작업자가 볼 필요가 있는 사유는 HMI에 표시합니다.

데이터 처리 흐름도

추천값은 정규화 좌표 → 실제 단위 가이던스 → 검증된 가이던스 → PLC 대기 레지스터 → 운전 Set-point 순서로 형태가 바뀝니다. 결과 이벤트는 반대 방향으로 돌아가 ② 비식별 경로를 통해 AI 측 학습 피드백이 됩니다.

기능별 시퀀스 다이어그램

핵심 기능 네 가지의 서버·서비스 간 호출 순서입니다. 실선은 요청, 점선은 응답이나 상태 판독, 굵은 파란 선은 역방향 다이오드 전송입니다.

① 가이던스 수신·검증·HMI 표시

가이던스는 사내 수신 서비스와 L1 가드에서 두 번 검사받은 뒤에야 PLC 대기 레지스터에 들어갑니다. 대기 레지스터에 있는 값은 운전에 반영되지 않으며, 자문 모드에서는 여기서 끝납니다.

② 작업자 승인·인터락·적용

작업자가 승인해도 PLC 인터락이 한 번 더 검사합니다. 적용 직전에 현재값을 LKG로 저장하고, 적용 후 감시 시간 동안 공정값이 벗어나면 자동으로 되돌립니다.

③ 한계 초과 차단

L1을 통과한 값을 PLC가 막았다는 것은 L1의 한계표 사본과 PLC 상수가 어긋났다는 신호입니다. 그래서 차단 이벤트가 나면 레지스트리가 PLC 상수를 다시 읽어 대조하고, 불일치를 경보로 올립니다.

④ 수동 롤백·통신 장애

두 경우 모두 PLC가 네트워크 없이 혼자 판단합니다. 해제된 AI 모드는 래치로 묶여 자동으로 다시 켜지지 않으며, 작업자가 원인을 확인하고 리셋해야 복귀합니다.

한계표 변경 절차 (참고)

한계값 변경은 변경관리(MOC) 절차로만 합니다. 현업 요청 → 공정·설비·안전 검토 → PLC 프로그램 상수 변경(서명된 프로젝트 파일) → HIL 시험 → 현장 반영 → 레지스트리 새 버전 등록 → 대조 일치 확인 순서입니다. 네트워크로 한계값을 바꾸는 기능은 만들지 않습니다.

단계별 구축 계획

계약서의 4단계 일정에 맞추되, 현장 PLC에 실제로 쓰기 전에 HIL 시험과 섀도 운전을 반드시 먼저 통과합니다. 1단계의 대상 Set-point와 한계표 확정(G1)이 이후 모든 설계의 기준입니다.

기간은 계약 기간(2026.08~2030.12)을 네 단계로 나눈 제안이며, ② 비식별 엔진의 배치 반출이 먼저 열려야 AI 모델이 학습해 추천을 낼 수 있다는 점을 반영했습니다.

리스크 및 확인 필요 사항

가장 큰 쟁점은 기술보다 안전 책임의 경계입니다. 한계값을 누가 정하고 승인하는지, 사고 시 책임을 어떻게 나누는지를 1단계에서 계약 문서로 확정해야 합니다.

리스크 영향 대응
AI 추천으로 인한 설비 손상·품질 사고 책임 분쟁 한계값은 현업이 제공·승인, 인터락 설계 범위와 책임을 계약서에 명시, 승인형 모드를 기본으로
기존 PLC 프로그램 변경에 대한 설비 공급사 보증 보증 상실, 변경 거부 1단계에 공급사 협의, 필요 시 공급사가 인터락 FB를 반영
압연 L2(셋업 모델)와 Set-point 충돌 두 시스템이 같은 값을 덮어씀 L2가 있으면 PLC 직접 쓰기 대신 L2의 작업자 보정값 인터페이스로 넣는 방식 검토
역방향 채널 보안 승인 지연 일정 지연 고정 스키마·허용 태그·서명·별도 다이오드로 공격면 최소화, 보안팀 조기 검토
작업자가 추천을 습관적으로 승인 (자동화 편향) 사실상 검토 없는 적용 근거와 변경 폭 표시, 큰 변경은 2인 확인, 승인율 모니터링
추천 유효시간보다 긴 처리 지연 쓸모없는 추천 라인별 지연 예산 정의, TTL 만료율 모니터링

확인 필요 사항

  • 대상 Set-point 목록과 라인별 PLC 기종·프로그램 변경 권한
  • 압연 L2 셋업 시스템 유무와 보정값 입력 인터페이스
  • 각 Set-point의 SOP 상·하한과 변화율 한계 (현업 제공)
  • 기존 SIS·설비 보호 계통과 AI 경로의 경계, SIL 요구 여부
  • 라인별 허용 지연 (압연 프리셋, 제강 가이던스)
  • 승인형·제한 자동 모드의 적용 승인권자
  • 역방향 다이오드 구매와 보안 인증 주체
  • 사고 시 책임 분담 문구 (계약서 반영)
