시스템 아키텍처

기술 스택

Backend: NestJS 11 TypeORM PostgreSQL 17
Frontend: Next.js 16 React 19 shadcn/ui Tailwind
폼/쿼리: React Hook Form + Zod TanStack Query/Table
수집: Benthos-UMH + OPC-UA + Avro
메시징: Kafka KRaft 4.x 3+ Broker + Schema Registry
캐싱: Valkey (Redis 호환)
모노레포: pnpm workspace + Turborepo
인증: apps/auth 별도 NestJS + nest-oidc-provider NEW
이메일: Listmonk Self-hosted NEW

데이터 흐름

PLC / 설비
↓ OPC-UA (opc.tcp://)
KEPServerEX (OPC-UA Server)
↓ HTTP API
Benthos-UMH (수집 엔진)
↓ Avro → Schema Registry
Kafka KRaft (3+ Broker)
↓ Kafka Connect (JDBC Sink)
TimescaleDB (시계열 저장)

MES/ERP/L2 (운영 데이터)
↓ NestJS Operational Pipeline
TimescaleDB / PostgreSQL

DB 이중 DataSource (Desired State → Reconcile)

df_package 마스터 데이터 (READ ONLY) OPC 서버·노드, Kafka 클러스터·토픽, 공장·설비·기기
df_app 운영 데이터 (READ/WRITE) users, streams, connections, RBAC, OIDC sessions
Cross-Schema는 FK 없이 uid 기반 loose reference. df_package는 Ansible/Terraform으로만 관리.

앱 간 의존 관계

apps/web → apps/auth (로그인, OIDC, 토큰 발급)
apps/web → apps/api (Bearer JWT, 데이터 API)
apps/auth → apps/api (JWT 검증: introspection)
apps/auth → Listmonk (가입·잠금 알림 메일)
apps/api → Listmonk (파이프라인 상태 알림)
apps/api → Benthos (스트림 배포 HTTP API)
apps/api → Kafka (토픽·연결 관리)
apps/api → SR (Avro 스키마 조회)
apps/api → KEPServer (OPC-UA 브라우징)
04

개발 정책 NEW

OPC-UA 수집 Class

Class A 실시간/라인 100ms ~ 500ms
Class B 배치/설비 1s ~ 5s
Class C 집계/운영 10s ~ 1min
보안: Basic256Sha256 / Sign & Encrypt
노드 네이밍: [Site].[Area].[Line].[AssetID]

Kafka 정책

클러스터: KRaft 3 Broker (Split-brain 방지)
Auto Create Disable — 명시적 토픽 생성만
Retention: 7일 / 50GB (파티션당)
Replication factor: 3, Min ISR: 2
압축: snappy (기본) / gzip/lz4/zstd 선택
Schema Registry: BACKWARD_TRANSITIVE
Kafka Connect Upsert (PK: asset_id, timestamp)

보안 정책

JWT: RS256 (apps/auth Private Key 서명)
Access Token: 15분 / Refresh: 7일
RBAC: admin > operator > viewer
로그인 실패 5회 → 계정 잠금 (loginAttempts)
Multi Auth: Local / Google OIDC / LDAP·AD / 외부 OIDC IdP NEW
도메인 화이트리스트: AUTH_ALLOWED_DOMAINS
로그 민감정보 마스킹: password, token, secret 등

네이밍 컨벤션

Kafka Topic
css.{bp}-{factory}.{source}-{dataset}
ex) css.changwon-fp.mes-heat-treat-extract-result

Stream ID = Kafka Topic (동일)
Connector {topic}.sink
Consumer Grp {topic}.timescale
DLQ Topic {topic}.error

Avro Subject css.{bp}_{factory}.{src}_{dataset}
DB Schema {bp}_{factory} → changwon_fp
DB Table {source}_{dataset}_tt

DB 테이블 접미어 규칙

_mtMaster Table정적 마스터 데이터 (corp_mt, device_mt…)
_ctCode Table코드성 데이터 (db_type_ct…)
_rtRelation TableN:M 관계 (equipment_device_rt…)
_htHistory Table이력 데이터 (benthos_deployment_ht…)
_ttTarget Table수집 결과 저장 (…_extract_result_tt)
v_View조회용 뷰 (v_tag_metadata…)
