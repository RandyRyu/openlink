02 · 단계별 상세

각 메시지가 하는 일

구현 위치와 동작 근거입니다. 연동 지점 행은 추가할 도구의 설계 의도입니다.

#구간메시지동작과 근거
1사용자 → 에이전트 루프호출 질문 입력main() → run_agent(question). messages = [{role: user, content: 질문}]
2에이전트 루프 → Claude API호출 messages.createmodel=ANTHROPIC_MODEL, max_tokens=4096. 도구 명세에는 '언제 쓰지 말 것'까지 들어 있어 도구 선택 정확도를 높인다
3Claude API → 에이전트 루프응답 stop_reason = tool_use규칙 1: 설비·라인·계측 지점은 다른 도구보다 먼저 resolve_entity 로 ID 를 확정
4에이전트 루프 → GraphTools호출 dispatch('resolve_entity', args)GraphTools.dispatch: 이름으로 메서드를 찾고, 예외를 not_found · invalid_argument · db_error 상태로 바꿔 돌려준다
5GraphTools → Neo4j호출 정확 일치 조회Equipment ∪ PhysicalAsset ∪ MeasurementPoint 를 UNION 으로 묶어 비교. 읽기 트랜잭션(execute_read), 타임아웃 10초
6Neo4j → GraphTools응답 1건샘플 데이터에서는 이름이 정확히 일치해 여기서 확정된다
7GraphTools → Neo4j호출 전문 검색질의어는 Lucene 이스케이프 후 cjk 바이그램 분석기 인덱스로 검색. '2번 공압기', 'COMP-02' 같은 별칭도 여기서 잡힌다
8Neo4j → GraphTools응답 후보 + score1위 점수가 2위의 1.5배 이상이면 resolved, 아니면 ambiguous, 결과가 없으면 not_found
9GraphTools → 에이전트 루프응답 status: resolved계층 경로(path_text)를 함께 돌려줘 LLM 이 후보를 사람처럼 구별할 수 있게 한다
10에이전트 루프 → Claude API호출 tool_result도구 결과를 JSON 문자열로 넣어 user 메시지로 추가. 오류 상태면 is_error=true
11Claude API → 에이전트 루프응답 stop_reason = tool_use × 5확정된 ID 로 필요한 목적형 도구를 한 번에 요청. 규칙 2: 목적형 도구 우선, run_cypher 는 마지막 수단
12GraphTools호출 _require(entity_id)모든 도구가 먼저 엔티티 존재와 라벨(Equipment 등)을 확인. 없으면 not_found + 'resolve_entity 로 먼저 확정' hint
13에이전트 루프 → GraphTools → Neo4j호출 get_flow(downstream) / (s)-[:FEEDS*1..3]->(t)가변 길이 상한은 정수로 검증 후 삽입(1~6). 대상별 최단 경로만 남김
14Neo4j → GraphTools → 에이전트 루프응답 경로 1개 / PC1 사출기 1호기 · compressed_air · 1홉공압기 2호기 정지 시 압축공기를 받는 PC1 사출기 1호기가 영향 범위
15에이전트 루프 → GraphTools → Neo4j호출 get_events / (ev)-[:OCCURRED_AT]->(e)하위 설비 포함(ancestor_ids), 최신순. INVOLVES 로 당시 실물 자산도 함께 조회
16Neo4j → GraphTools → 에이전트 루프응답 3건 / EV-0621 · EV-0588 · EV-0412(과전류, AS-COMP-A101)전력계 교체, 실물 교체, 과전류 트립. 과전류는 교체 전 실물(A101)에서 발생
17에이전트 루프 → GraphTools → Neo4j호출 find_documents / (d)-[:ABOUT]->(x)역할 자체, 상위 계층, 그 역할을 맡았던 모든 실물의 문서를 함께 찾는다
18Neo4j → GraphTools → 에이전트 루프응답 3건 / DOC-SOP-COMP · DOC-INC-2026-031 · DOC-MAN-SA75VSOP, 장애보고서(과거 실물), 현재 실물 B200 의 매뉴얼. 본문은 없고 ID·URI 만
19에이전트 루프 → GraphTools → Neo4j호출 get_aas_reference(at=now) / FULFILLS 유효기간 · MADE_BYvalid_from ≤ at < valid_to 인 실물을 찾고 제조사와 AAS 식별자를 읽는다
20Neo4j → GraphTools → 에이전트 루프응답 1건 / AS-COMP-B200 · globalAssetId · aas_idglobalAssetId = https://www.sampleair.example/id/AC-2026-0112 (제조사 부여 ID)
21에이전트 루프 → GraphTools → Neo4j호출 get_measurement_points(at=now) / MEASURES · SOURCE_OF 유효기간측정 지점과 지금 유효한 OPC UA 태그. 시계열 값은 반환하지 않음
22Neo4j → GraphTools → 에이전트 루프응답 2건 / MP-COMP02-KW → TAG-PM0110-P · kWh → PM0110-E서버 KEPServerEX-GS01, NodeId ns=2;s=PowerMeters.PM0110.ActivePower
23에이전트 루프 → Claude API호출 tool_result × 5tool_use_id 별 결과 5개를 한 번에 넣는다
24Claude API → 에이전트 루프응답 tool_use: search_docs · query_metric · get_nameplate 연동 지점추가할 도구. 모두 그래프가 준 ID 를 입력으로 받는다
25에이전트 루프 → 벡터 DB호출 유사도 검색 연동 지점find_documents 결과로 범위를 좁힌 뒤 질문 임베딩으로 검색. 엉뚱한 설비 문서가 섞이지 않는다
26벡터 DB → 에이전트 루프응답 원인·조치 문단 연동 지점장애보고서 본문의 근거 문단
27에이전트 루프 → TSDB호출 query_metric(MP-COMP02-KW, 기간) 연동 지점get_tag_history 의 기간별 태그로 시계열을 끊김 없이 이어 붙인다. 계산식은 지표 정의(시멘틱 레이어)가 고정
28TSDB → 에이전트 루프응답 시계열 · 집계값 연동 지점LLM 은 숫자를 계산하지 않고 받은 값을 인용
29에이전트 루프 → AAS Repository호출 GET /submodels/{base64url(id)} 연동 지점get_aas_reference 가 준 nameplate_submodel_id 로 원본 조회 (IDTA 01002 API v3)
30AAS Repository → 에이전트 루프응답 제조사 · 주문코드 · 제조일 연동 지점현재 설치 장비의 명판 정보
31에이전트 루프 → Claude API호출 tool_result 연동 지점연동 결과도 같은 방식으로 전달
32Claude API → 에이전트 루프응답 stop_reason = end_turn규칙 4: 수치를 지어내지 않음. 규칙 6: 근거 ID 표기. tool_use 가 없으므로 루프 종료
33에이전트 루프 → 사용자응답 답변text 블록만 이어 붙여 출력. 12턴을 넘기면 중단 메시지를 반환
03 · 분기와 실패 경로

정상 흐름에서 벗어나는 경우

resolve_entity → ambiguous / not_found

이름이 모호하거나 없을 때

후보와 계층 경로를 돌려주고, LLM 은 경로로 고르거나 사용자에게 되묻습니다. 결과에 “ID 를 추측하지 마세요” hint 가 붙어 다음 도구 호출이 멈춥니다.

목적형 도구로 답할 수 없을 때

run_cypher 로 넘어갈 때

get_schema 로 스키마를 확인한 뒤 run_cypher 를 호출합니다. 쓰기 구문 차단 → EXPLAIN 문법 검사 → 없는 라벨·관계·속성이면 실행 전 schema_mismatch 반환 → 읽기 트랜잭션 실행 순서이고, 실패하면 hint 를 보고 최대 2회 고쳐 다시 시도합니다.

결과 0건 · 12턴 초과

빈 결과와 무한 반복 방지

0건이면 “없다”고 단정하지 말고 ID·관계 방향·시점 조건을 다시 확인하라는 hint 가 붙습니다. 도구 호출이 12턴을 넘기면 루프가 중단 메시지를 돌려주고 끝납니다.
