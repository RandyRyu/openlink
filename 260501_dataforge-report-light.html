v1.0 → 현재까지 확정된 아키텍처·요구사항·구현 변경
인증 시스템
Keycloak→Zitadel→oidc-provider→apps/auth 독립 (v1.5)
nest-oidc-provider 기반 OIDC Provider를 apps/auth (Port 3002)로 독립 분리. Multi Auth Strategy 4종 (Local / Google OIDC / LDAP·AD / 외부 OIDC IdP). RS256 JWT, JWKS 공개. apps/api는 Bearer JWT 검증에 집중.
수집 엔진
NiFi→Benthos-UMH (실운영 중)
OPC-UA 네이티브 지원 + Virtual Tag + Bloblang 변환. 4 processors 확정: except_system_nodes → filter_bad_quality → bool_to_int → opcua_schema_registry. 소형압연 892태그, 일 2,500만 건 실운영 검증.
KEPServer 제어 방식
KEP = SSoT, DB = 미러→DF-Stream이 KEP 유일 창구 (DFSTREAM-336, 4/22)
Tag 생성 = KEP 노드 생성 (2-phase all-or-nothing). DB 먼저 저장 후 KEP에 Push. KEP 실패 시 DB 롤백 + PUSH_FAILED 기록. ownership 기반 Strangler Fig 패턴으로 기존 현장 보존. T1~T6 머지 완료(4/22).
DB 구조
단일 DB→df_package (47 테이블) + df_app (12 테이블)
df_package는 인프라 마스터 + 표준 사전(data_standard) 포함 47개 테이블로 확정. df_app은 Phase 1 기준 12개 테이블. Cross-Schema FK 없이 uid loose reference.
Stream Wizard 경로
4단계 단일 경로→Quick Deploy + Advanced Deploy (2경로)
Quick Deploy: 공장 선택 → 수집 태그 선택 (라이브 OPC UA 노드 브라우저) → 미리보기+배포 (3단계). Advanced Deploy: 기존 4단계 (OPC UA → Kafka → Schema+Pipeline → Deploy). 공통 6단계 오케스트레이션 후 완료.
운영 데이터 파이프라인
Python/FastAPI 별도→NestJS apps/api 통합 (v1.6)
MES/ERP/L2 DDL 입력 → 6단계 자동 파이프라인(DDL→PostgreSQL→Avro→SR→Kafka Connect→Benthos→TimescaleDB). DDL Parser (Oracle/MySQL/PostgreSQL). Compensating Transaction 롤백 지원.
이메일 서비스
Listmonk Self-hosted 추가 (v1.7)
Self-hosted 트랜잭션 이메일(Go). users ↔ Listmonk Subscriber 동기화. apps/auth(가입·잠금 알림) + apps/api(파이프라인 알림) 연동.
표준 사전 체계
단어→용어→도메인 3계층 SSoT (의미론 SSoT 확립)
모든 명칭·정의의 원본은 표준 사전(data_standard). 단어(Word)→용어(Term)→도메인(Domain) 3계층. factory·equipment·device·tag가 standard_term_uid FK로 사전 참조. ISA-95 Class/Instance 구분 명확화. AI 이상탐지 기준값 자동 도출 기반.
Equipment 계층 구조
ISA-95 기반 ReactFlow 다이어그램 (DFSTREAM-339, 4/22)
Equipment는 물리 장비가 아닌 추상 그룹(ISA-95 Work Unit / SAP Functional Location). /standard-data/equipments 페이지가 @xyflow/react + @dagrejs/dagre 자동 레이아웃 관계 다이어그램으로 개편. equipment_mt.standard_term_uid FK 필수 강제.
컨테이너
Docker Swarm→K3s (Kubernetes) 채택
K3s + Headlamp 구성 완료. TimescaleDB SSD 이관, Kafka KRaft 4.2 운영 환경 구축.

시스템 아키텍처 가이드 NEW 2026-04-28

601KB · 23개 섹션 · 아키텍처 설계의 종합 레퍼런스
핵심 원칙 — 두 개의 SSoT
원칙 1 — 인프라 SSoT
모든 파이프라인 설정의 원본은 DF-Stream DB에 있다. Benthos·Kafka·SR은 DB 내용을 반영한 결과물일 뿐. 직접 조작 금지. DB → SR → Benthos → KafkaConnect 순 6단계 오케스트레이션 필수.
원칙 2 — 의미론 SSoT
모든 데이터의 정의·명칭 원본은 표준 사전 (data_standard)에 있다. 각 엔티티는 standard_term_uid FK로 사전을 참조할 뿐. 사전에 고유명사 직접 등록 금지.

1:1:1:1 정책 — 공장 단위 파이프라인 격리

공장(Factory) 1:1 Stream(Benthos Pipeline) 1:1 Kafka Topic 1:1 Connector(JDBC Sink) 1:1 DB Table(tag_rt) 예: changwon_srl 공장의 경우 공장 : changwon_srl Stream : changwon-srl-kepserver1-01 Topic : css.changwon_srl.tag Connector : css.changwon_srl.tag.sink DB Table : changwon_srl.tag_rt
한 공장 장애가 다른 공장에 영향 없음. 독립 운영·장애 추적·스키마 분리 보장.

DFSTREAM-336 POC — KEPServer 단일 창구 (4/22 완료)

Tag Lifecycle 상태 전이
[*] DRAFT→address 없이 생성 (관리자가 이후 Activate)
PENDING_PUSH→address 있는 생성, KEP push 전
ACTIVE←→KEP push 성공, retry-push로 복구 가능
PUSH_FAILED→KEP push 실패, DB 행 유지 + 에러 상세
ORPHANED→KEP에서 삭제됨, Drift Detection 감지
ownership 기반 Strangler Fig: LEGACY(기존 현장) / DF_STREAM_OWNED(신규) / KEP_OWNED / SHARED

Benthos Pipeline — 4 Processors 확정

① except_system_nodes _* · ns=0;* · nodeid i=* 필터
② filter_bad_quality statuscode !contains 'Good' → drop
③ bool_to_int Boolean 값 → INT 변환
④ opcua_schema_registry schema_registry_encode (Avro)

통합 동기화 엔드포인트

POST /api/opc-servers/:uid/sync ─── Config API 사용 가능 시 ─────────────────── 엔진 : syncFullTree 범위 : drivers + channels + devices + tags + device_mt + auto-mapping ─── Config API 미사용 시 ────────────────────── 엔진 : browseRecursive 범위 : OPC UA 노드 트리만 (browse) ─── Frontend 단일 훅 ────────────────────────── const { mutate: sync } = useSyncOpcServer(uid); sync(); // Config API 여부에 따라 자동 분기
